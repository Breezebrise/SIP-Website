Student Innovation Project

AI Efficiency Benchmarking for Cybersecurity Analysis

A tool that tests whether AI in security analysis actually earns the energy it uses.

Innovation claim

This framework runs the same network traffic through an AI pipeline and a traditional rule-based pipeline, then scores both on detection accuracy, false positive rate, processing time, and carbon emissions. Nothing currently available compares AI and non-AI security analysis on accuracy and environmental cost side by side, so security teams are adopting AI tools without evidence that the tradeoff is worth it.

Project description

AI is being built into security products as a default feature. Vendors advertise better detection, but nobody publishes what that detection costs in compute and emissions, or whether a well-tuned traditional tool would have caught the same traffic. SOC teams end up paying for AI they can't evaluate, and junior analysts lose the hands-on reps that build real skill.

My project answers the question directly. The tool takes a labeled packet capture and runs it through two pipelines. One uses Zeek with detection rules, the way many SOCs already work. The other uses a machine learning classifier built with scikit-learn. Both pipelines are wrapped with CodeCarbon, which measures the energy used and estimates emissions in kilograms of CO2 equivalent. The output is a single comparison report that shows what each approach caught, what it got wrong, how long it took, and what it cost to run.

The goal is a benchmark any security team can rerun on their own traffic before deciding whether an AI tool belongs in their stack.
